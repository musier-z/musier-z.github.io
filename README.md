# Robotaxi Tracker 简体中文版

原站：<https://robotaxitracker.com/>。镜像制作日期：2026 年 11 月 3 日。

保留原站公开页面的深色布局、响应式样式、客户端路由、车辆搜索与筛选、交互图表、服务范围地图和车辆详情。导航、页面正文、提示、筛选条件和动态公开数据使用简体中文。品牌、VIN、车牌、来源链接等保留识别信息。

## 启动

需要 Python 3.9 或更新版本，无需安装第三方依赖。

```sh
python3 server.py --port 8765
```

打开 <http://127.0.0.1:8765>。服务默认只监听本机；容器部署时可用 `python3 server.py --host 0.0.0.0 --port 8080`。

## 内容和数据

- `public/assets/`：本地保存的原站前端资源，保留原始文件名和交互逻辑。
- `zh-cn.js`：页面、属性、图表文字和动态内容的中文处理。
- `public/glossary.js`：人工校对的术语和关键统计说明，优先于机器翻译。
- `translations.json`：已缓存的中文词库，可随项目迁移。
- `cache/`：公开数据与图片缓存。配套 `.json` 文件记录原始路径、请求参数及抓取时间。
- `server.py`：本地网页服务与公开数据读取。
- `refresh.py`、`refresh-config.json`：缓存管理、分级检查、失败重试与可调整的更新间隔。
- `refresh-ui.js`、`refresh-ui.css`：中文更新状态与手动更新面板。
- `mirror-manifest.json`：前端资源清单。

数据以原站为来源，保留原统计日期、估算说明和原始计量单位。服务运行且联网时按下表自动检查已收录的数据；**镜像成功检查时间不代表原始数据的统计日期，也不保证原站已发布新数据**。地图底图和未缓存的公开内容需要联网。未收录的可见英文由浏览器调用 Google 翻译，再保存到本地词库；网络不可用时保留可读原文，避免隐藏信息。

前端直接引用的 20 份公开静态数据已全部缓存，包括居民热力图网格。缓存清单见 `data-manifest.json`；首次访问的动态接口及外部地图瓦片仍需联网。

登录、注册、投稿和账户管理提示前往原站，不收集原站账户密码，也不向原站提交修改。外部新闻全文、应用商店和周报链接保留原目标；本地翻译覆盖站内展示内容。

## 自动数据更新

默认开启，无需另外设置操作系统定时任务。右下角「数据更新」可查看各类数据检查状态、最早成功检查时间、失败条数和手动更新进度。

| 数据类别 | 默认检查间隔 | 说明 |
| --- | --- | --- |
| 摄像头最新发现与实时计数 | 1 分钟 | 接近原站前端的轮询节奏 |
| 候车时间 | 2 分钟 | 原站说明采集器每隔几分钟采样 |
| 车辆目录、排行榜、摄像头时序统计 | 5 分钟 | 兼顾变化速度与抓取量 |
| 新闻 | 30 分钟 | 适合资讯浏览 |
| 得州登记、服务范围、价格、舆情、全国车队估算 | 1 小时 | 原站说明得州 VIN 登记每小时检查 |
| NHTSA / CPUC、加州和亚利桑那登记快照、里程、其他历史统计与周报 | 6 小时 | 检查原站是否发布了新快照，保留各自统计日期 |
| 人口地理与地图样式 | 1 天 | 变化较慢 |
| 历史分页和单条舆情帖子 | 1 天，按访问触发 | 避免持续重抓已翻阅的旧分页 |

车辆和公开用户详情使用 5 分钟有效期，按访问更新，不长期后台轮询。图片按现有地址缓存；前端 JS/CSS、HTML 入口、人工术语表和翻译词库不会被定时替换。自动更新只覆盖已缓存或访问过的数据，不主动遍历整站；新打开模块在首次访问时收录。

间隔为建议值，而非原站承诺的发布周期。依据原站 2026-11-03 的方法说明（`https://robotaxitracker.com/methodology`）以及本地固定版本的前端轮询配置。无需每分钟下载历史统计和大体积人口网格。

更新行为：

- 最多每 15 秒检查调度队列，请求完成后立即继续处理到期数据，最多 3 个原站请求并行；到期时间是最早可检查时间，排队、网络耗时和失败退避可能延后检查。
- 缓存到期时先返回上次成功数据，在后台更新；无缓存时才等待首次抓取。相同路径和请求参数的并发请求会合并。
- 支持 GET 的 ETag / Last-Modified 条件请求。HTTP 304 或内容完全相同时仅更新成功检查时间，不宣称数据内容发生变化。
- HTTP 错误、无效 JSON、错误响应、主要集合字段结构变化时，保留成功缓存；常规失败按 1、2、4、8…分钟退避，最长 1 小时，并遵守原站更长的 `Retry-After`。手动更新也不会绕过退避。
- 原站返回 HTTP 401 / 403 时停止该数据的自动和手动抓取，单独标记「访问受限」，保留旧缓存。已确认禁止自动访问的路径也可列入 `blockedPaths`。2026-11-03 实测 `/v1/waymo-cameras?cameras=tally` 返回 HTTP 403、`automated_client`，因此已将 `/v1/waymo-cameras` 加入该列表；这一模块目前不自动同步。只有确认原站已允许访问后才应解除限制，不通过伪装请求绕过。
- 新内容先写完整文件，再原子替换元数据指针；中途中断不覆盖上次成功缓存。每组数据的检查状态及退避记录随缓存保存，重启继续使用；手动任务的进度仅保留在本次运行内。
- 手动更新检查全部已收录的可变数据（含访问过的详情和旧分页，排除图片），后台运行并报告变化、无变化、失败、退避等待。任务执行中复用同一任务；两次手动启动至少间隔 1 分钟。
- 页面已有的实时模块继续按照原站程序轮询。其他打开的图表会提示「有新数据」，点击「重新载入页面」应用最新缓存；不会自动打断筛选或地图操作。重新载入会重置临时页面状态。
- 服务停止、电脑休眠或断网时无法继续定时同步。恢复后按到期时间补查，不补跑每一次错过的定时任务。若要全天更新，需将服务持续运行在联网主机上。

修改 `refresh-config.json` 后重启服务生效。`intervalsSeconds` 单位为秒；`enabled: false` 关闭自动检查，仍可手动检查及首次抓取。可用 `REFRESH_CONFIG` 环境变量指定另一份配置文件。`workers` 限制并发，`requestTimeoutSeconds` 控制单次请求超时。一个缓存目录只运行一个服务进程；容器长期部署时应持久保存 `cache/` 和翻译词库。

`GET /__local/refresh-status` 返回状态（UTC 时间，面板转为本机时区）；`POST /__local/refresh` 携带 `X-Mirror-Action: refresh` 和 JSON 请求体发起手动检查。只读取原站公开接口。公开数据响应带 `X-Mirror-Cache`、`X-Mirror-Checked-At`、`X-Mirror-Changed-At` 等本地缓存标记，不改写原站数据里的时间。

旧缓存记录仅有 `fetchedAt`；初始成功检查时间沿用该时间，内容变化时间保持未知，直到实际检测到内容变化。新缓存的 `.json` 中 `bodyFile` 指向有效响应文件；不要假定它仍是同名 `.body`，也不要在服务运行时删除配对文件。

验证命令：`python3 -m unittest -v test_refresh.py`。测试覆盖过期刷新、并发去重、请求参数隔离、304、失败回退、退避、缓存迁移、原子提交、定时分类和手动更新。

## 更新资源与校正翻译

`mirror.py` 保留本次已核实的前端版本，补齐缺失资源。原站换版后，应同步修改入口文件和依赖清单后再更新，避免混用不兼容的数据结构。

修改术语优先编辑 `public/glossary.js`，然后更新 `index.html` 中的版本参数并刷新页面。`python3 extract_strings.py` 可重新提取公开界面的静态文字。需要检查原站新数据时，优先使用页面的「立即检查更新」。

## GitHub Pages 静态版

Pages 只能托管静态文件，所以 `.github/workflows/pages.yml` 在推送到 `main`、每小时定时（第 17 分）和手动触发时运行：先跑单元测试，再用 `build_static.py` 生成 `dist/` 并发布。

- `build_static.py` 复用 `refresh.py` 的规则：只读公开接口，遵守 `blockedPaths`、401/403 停止、失败退避、ETag/304 和失败时保留旧副本；`cache/` 通过 Actions 缓存在两次运行间保留，不提交到仓库。
- 要抓取的接口来自 `static-endpoints.json`（由 `tools/discover_endpoints.py` 对本地服务实际页面请求录制）以及前端包里引用的 `/data/*.json`。下一页、帖子详情和图片只从已抓取数据中出现的地址派生（有数量上限）。
- `static-shim.js` 在浏览器中把前端的 `/v1/…`、`/data/…`、`/map-styles/…` 请求映射到 `data-snapshot/` 中的文件，并为项目子路径（如 `/robotaxi-tracker-zh/`）补全资源地址。
- 本地预览：`python3 build_static.py --out dist --base /`，然后在 `dist/` 中启动任意静态文件服务。

静态版的限制：数据最多约一小时更新一次（不是实时轮询），页面上没有「立即检查更新」；翻译缓存无法写回（浏览器内的机器翻译仍可用）；受原站限制的 Waymo 摄像头数据不可用；单车详情等未在快照中的页面和未快照的图片会提示前往原站或直接从原站加载；账户、登录和投稿功能请前往原站。
